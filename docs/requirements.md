## 1. Термины и определения

| Термин | Определение |
|---|---|
| **Заключительная дезинфекция** | Комплекс мероприятий, проводимых в очаге туберкулёзной инфекции после госпитализации, выписки или смерти больного, для полного уничтожения возбудителя. |
| **Сотрудник диспансерного отделения** | Врач-фтизиатр или медицинская сестра диспансерного отделения. В текущей версии системы их функциональные роли совмещены — оба имеют одинаковые права по созданию и отслеживанию заявок. |
| **Дезинфектор** | Сотрудник отдела эпидемиологии и профилактической дезинфекции, выполняющий обработку очагов и фиксирующий результаты в системе. |
| **Очаг (эпидемический очаг)** | Адрес (квартира, дом, общежитие и т.д.), где проживает или проживал больной туберкулёзом и где необходимо провести заключительную дезинфекцию. |
| **Заявка** | Электронный документ, создаваемый сотрудником диспансерного отделения, содержащий сведения об очаге, пациенте и необходимых дезинфекционных мероприятиях. |

## 2. Цели и задачи системы

### Цель
Автоматизировать процесс подачи, обработки и учёта заявок на заключительную дезинфекцию очагов туберкулёзной инфекции, исключить ручной ввод, дублирование данных и потерю информации.

### Задачи
- Перевести бумажные заявки в электронный формат с веб-интерфейсом.
- Обеспечить валидацию входных данных при создании заявки.
- Автоматизировать маршрутизацию заявок в дезотдел и обратную связь.
- Реализовать уведомления в реальном времени о создании и изменении статуса заявки.
- Обеспечить автоматическое формирование статистики и отчётов за выбранный период.
- Соответствовать требованиям законодательства РФ в области защиты персональных данных (152-ФЗ).

## 3. Роли пользователей

| Роль | Права и обязанности |
|---|---|
| **Сотрудник диспансерного отделения** | Создание и редактирование заявок, отслеживание статуса своих заявок, экспорт бланка заявки в DOCX. |
| **Дезинфектор** | Просмотр назначенных заявок, изменение статуса заявки, внесение данных о выполненной дезинфекции (дата, площадь, результат, примечания), экспорт данных в Excel. |
| **Администратор** | Управление пользователями (создание, редактирование, деактивация), просмотр всех заявок, доступ к модулю статистики и отчётности, публикация новостей в блоге. |

## 4. Функциональные требования

Требования сгруппированы по ролям пользователей и пронумерованы в формате `DRS-FR-XX`.

### 4.1. Сотрудник диспансерного отделения

| ID | Функция | Описание |
|---|---|---|
| **DRS-FR-01** | Создание заявки с валидацией и подсказками | Сотрудник заполняет электронную форму заявки. **Обязательные поля:** адрес очага (автодополнение по г. Якутску), диагноз (выбор кода МКБ-10 по туберкулёзу), группа диспансерного учёта (список), эпидемическая группа (список), выбор врача с автоподстановкой участка, контактный номер (валидация и автоформатирование). Если номер принадлежит не пациенту, а встречающему лицу — дополнительное поле для данных встречающего. При отсутствии врача в справочнике — автосоздание из введённых ФИО и участка. Все поля обязательны. После отправки заявке присваивается статус «В работе». |
| **DRS-FR-02** | Просмотр списка всех заявок с поиском | Доступна таблица со всеми заявками учреждения (дата, адрес, статус, участок/отделение). Строка поиска по адресу, ФИО пациента, номеру, участку. Фильтр по статусу. Клик по строке открывает детальный просмотр заявки. |
| **DRS-FR-03** | Редактирование и экспорт заявки | Редактирование доступно только для заявок со статусом «В работе». Открывается предзаполненная форма создания. Кнопка «Скачать заявку» формирует DOCX-файл по утверждённому шаблону учреждения. |
| **DRS-FR-04** | Отслеживание статуса заявки и уведомления | В списке заявок статус выделяется цветом. При изменении статуса дезинфектором автор получает уведомление в интерфейсе. В карточке заявки отображается история изменений статуса с датой и временем. |
| **DRS-FR-05** | Просмотр статистики по участкам и эпидгруппам | Отображается статистика за выбранный период (месяц, квартал, полугодие, 9 месяцев, год). Таблица: Участок \| Эпидгруппа \| Подано заявок \| Исполнено заявок \| в т.ч. по смертности. Возможность экспорта отчётности в DOCX. |

### 4.2. Сотрудник дезинфекционного отдела

| ID | Функция | Описание |
|---|---|---|
| **DRS-FR-06** | Просмотр новых заявок и выгрузка в DOCX | При входе отображается список заявок со статусом «В работе». Кнопка «Скачать заявку» формирует DOCX-файл по шаблону учреждения для выдачи бригадам. |
| **DRS-FR-07** | Внесение данных о выполненной обработке | В карточке заявки доступна форма «Внести данные». Поля: обработанная площадь (кв.м), количество смывов для контроля качества, исполнители (выбор нескольких дезинфекторов из списка). После сохранения статус автоматически меняется на «Выполнена». Дата и время фиксируются автоматически с возможностью ручной корректировки. |
| **DRS-FR-08** | Оформление отказа от дезинфекции | В карточке заявки доступен чекбокс «Отказ». При его установке появляется обязательное поле «Причина отказа». После сохранения статус меняется на «Отказ». Заявка попадает в отчёты по отказам. Дата и время фиксируются автоматически. |
| **DRS-FR-09** | Автоматическая отчётность по периодам и полная выгрузка | Раздел «Отчёты» с выбором периода (месяц/квартал/полугодие/год). Показатели: поступившие заявки, проведённые обработки, отказы, количество смывов, суммарная обработанная площадь, разбивка по эпидгруппам и участкам. Экспорт отчёта в DOCX. Кнопка «Загрузить в EXCEL» формирует файл со всеми заявками за период (адрес, дата, статус, исполнитель, площадь, смывы). |
| **DRS-FR-10** | Рейтинг дезинфекторов и полная выгрузка | Отображается рейтинг за выбранный период: ФИО дезинфектора, количество заявок, средняя площадь обработки (кв.м). Визуализация в виде диаграммы «Топ дезинфекторов». |

### 4.3. Администратор

| ID | Функция | Описание |
|---|---|---|
| **DRS-FR-11** | Управление пользователями и аудит | Раздел «Пользователи» со списком учётных записей. Кнопки: добавить, редактировать роль, удалить. Роли: «Сотрудник диспансера», «Дезинфектор», «Администратор». Раздел «Журнал событий» с фильтром по дате, пользователю, типу действия. Логируются: создание/редактирование/удаление заявок, изменение статусов, вход в систему. |
| **DRS-FR-12** | Полный доступ к заявкам и отчётности | Доступ ко всем заявкам без ограничений. Доступны кнопки создания, редактирования и удаления любой заявки. Доступ ко всем отчётам дезинфекторов. |
| **DRS-FR-13** | Управление новостным блоком | Раздел «Новости» в административной панели. Добавление, редактирование, удаление новостей (заголовок, текст, дата публикации). Лента новостей отображается на главной странице для всех ролей. |

## 5. Нефункциональные требования

### 5.1. Доступность и надёжность
- Система доступна через веб-браузер из всех корпусов учреждения (в пределах локальной сети).
- Время отклика на типовые запросы — не более 2 секунд.
- Автоматический перезапуск контейнеров при сбоях (Docker restart policy).

### 5.2. Совместимость
- Клиентская часть работает в актуальных версиях браузеров (Chrome, Firefox, Edge).
- Серверная часть разворачивается на Linux (Ubuntu 20.04+) с использованием Docker.

### 5.3. Масштабируемость
- Архитектура позволяет увеличить количество экземпляров приложения при росте нагрузки (stateless-подход, вынесение статики на Nginx).

### 5.4. Безопасность персональных данных (152-ФЗ)
Система обрабатывает специальную категорию персональных данных — сведения о состоянии здоровья пациентов. При проектировании учтены требования Федерального закона от 27.07.2006 № 152-ФЗ.

Предварительная оценка в соответствии с Постановлением Правительства РФ № 1119 позволяет отнести систему к **3 уровню защищённости (УЗ-3)**. В архитектуру заложены следующие организационные и технические меры в соответствии с Приказом ФСТЭК № 21:

## 6. Рамки проекта (Scope)

### Входит в текущую версию
- Подача заявок диспансерными отделениями (4 подразделения).
- Обработка заявок дезотделом (изменение статуса, внесение результатов).
- Базовый модуль отчётности и статистики.
- Администрирование пользователей.
- Блог для публикации новостей.

### Не входит (возможное развитие)
- Модуль оказания платных дезинфекционных, дератизационных и дезинсекционных услуг.
- Мобильное приложение для выездных бригад.
- Интеграция с федеральными системами учёта (ЕГИСЗ).
- Модуль планирования ресурсов и расписания выездов.
